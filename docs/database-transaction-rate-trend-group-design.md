# 数据库平均事务速率：趋势分组数详细设计

日期：2026-10-14。

适用范围：NOP“编辑数据”弹窗中的数据库／数据库客户端趋势分析，重点说明“平均事务速率”和“趋势分组数”。本文依据当前源码与原 NetInside DPM 请求模板整理，包含现状、设计决策、待确认的后端契约及实施验收方案。本次交付为文档。

## 1. 核心定义与证据边界

**“趋势分组数”的设计含义，是在选定节点、时间和趋势指标下，向数据源请求多少个查询趋势分组。请求以 `QUERY_TEXT`（SQL／查询文本）作为聚合字段，前端按响应的 `Group` 分别展示曲线。**

对“平均事务速率”而言，每条曲线设计上用于观察一个查询组的事务速率随时间的变化。

需要区分两个层次：

| 层次 | 当前依据 | 可以确认的内容 |
| --- | --- | --- |
| 请求设计 | `aggrField=QUERY_TEXT`、`top=limit` | 请求要求按查询文本维度聚合，并传递所需分组数量 |
| 前端展示 | `normalizeSeries` 按返回的 `Group` 建立系列 | 不同返回分组分别绘制，不在前端自行生成 SQL 分组 |
| 数据源契约 | 本专题尚未完成真实接口验证 | 不能确认 SQL 是否归一化、Top 按什么排序、是否严格限制数量，以及所有 `Group` 与查询文本的对应方式 |

因此，“按 SQL／查询文本分组”是当前参数表达的设计意图；不能把它进一步写成“后端已确认按归一化 SQL 指纹分组”。现有实例 × 命令的计数验收，也不能替代本专题的趋势分组验收。

## 2. 业务对象与分析层级

截图中的配置可理解为以下层级：

```text
数据库数据源：236
  └─ 分析对象：数据库
      └─ 数据库节点：238
          └─ 查询时间：2026-10-13 00:00 至 2026-10-14 00:00
              └─ 查询文本维度的趋势分组：由数据源返回
                  ├─ 查询组 A → 平均事务速率随时间变化
                  ├─ 查询组 B → 平均事务速率随时间变化
                  └─ ……
```

上面的查询组 A、B 是说明用的匿名名称，不是该节点的实际接口结果。

| 名称 | 表示什么 | 与趋势分组的关系 |
| --- | --- | --- |
| 数据源 | 提供数据库分析接口的服务 | 决定查询发往哪里；本场景业务后端为 236 |
| 数据库节点 | 当前分析的被监控数据库节点 | 限定查询范围；与数据源地址不同 |
| 数据库实例 | 数据库实例分析中的分类对象 | 不是本控件的分组数量含义 |
| 查询命令 | SELECT、INSERT 等命令类别 | 与查询文本分组不同；当前趋势请求没有按 `QUERY_COMMAND` 聚合 |
| 查询文本分组 | 数据源依据 `QUERY_TEXT` 组织的查询组 | 是当前趋势请求要求的聚合维度 |
| 时间点 | 曲线横轴上的实际时间戳 | 是每个分组中的样本位置，不是一个分组 |

数据库客户端采用同样的趋势分组设计，但节点条件换为 `CLIENT_NODE_ID`。该范围可能涵盖该客户端访问的数据库查询；具体覆盖范围需按客户端接口契约验证，不能直接套用数据库节点的范围定义。

## 3. 平均事务速率的含义

平均事务速率表示数据源返回的、对应统计时间位置或统计段的事务发生速率。当前趋势请求的指标标签为：

```text
Average Transaction Rate (#/min)
```

默认单位为次/分钟；前端优先识别响应表头中的实际单位，不只根据中文名称确定单位。

| 项目 | 解释 |
| --- | --- |
| 横轴 | 数据源返回的真实时间戳 |
| 纵轴 | 该查询组在相应时间位置的事务速率 |
| 一条曲线 | 一个返回分组的一种趋势指标 |
| 图例 | 当前实现组合“指标名称”和返回的分组标签 |
| 提示信息 | 时间、分组／系列名称、数值和单位 |

“平均”对应服务端的指标定义，不表示前端会把返回的多条曲线再平均，也不表示用整个查询区间计算一个固定速率。统计段长度、分母、采样窗口及归一化算法尚需后端确认。

若响应明确给出次/秒，则按该单位表达；没有验证服务端口径前，不自动乘 60、除 60或用速率反推事务总数。

## 4. 趋势分组数的职责

### 4.1 当前参数映射

```text
界面“趋势分组数”
    → databaseQuery.limit
    → 请求参数 top
    → 后端选择与返回分组
    → 前端按实际 Group 建立曲线
```

当前趋势默认值为 5，界面及查询校验接受 1 至 1000 的整数。该范围是当前前端约束，不是已经验证的服务端支持上限。

例如，设为 5 会发送 `top=5`。设计意图是请求 Top 5 查询趋势分组；实际可能只返回 1 组、3 组，或出现数据源未严格执行数量限制的情况。前端按真实响应展示，不为凑足数量生成分组。

### 4.2 它不控制的内容

| 容易混淆的含义 | 正确解释 |
| --- | --- |
| 5 个数据库节点 | 节点由上方节点选择器指定 |
| 5 个数据库实例 | 当前趋势请求没有改为实例聚合 |
| 5 个趋势指标 | 指标由“数据库指标”选择项决定 |
| 5 个时间点 | 时间点由数据源返回 |
| 每 5 分钟采样 | 该值没有映射为采样间隔 |
| 把速率除以 5 | 前端没有这种数值计算 |
| 最活跃的 5 组 SQL | 当前趋势请求没有显式指定 Top 排序指标，不能承诺按查询次数排序 |
| 严格只绘制 5 条线 | 实际分组数、指标数和服务端限制共同影响曲线数 |

### 4.3 分组数与曲线数

在截图所示只选“平均事务速率”的情况下，后端返回 3 个不同 `Group`，前端会建立 3 个系列。

若以后在同单位的趋势图中同时选择两种指标，当前执行器会分别发起两个请求，每个请求都使用同一个 `top` 值。分组集合可能不同，整个图的系列数不能简单解释为“趋势分组数”。平均事务速率和响应时间单位不同，当前组件校验要求分别配置图表。

## 5. 为什么采用这一设计

| 设计决策 | 原因 |
| --- | --- |
| 节点范围与趋势分组数分开 | 节点回答“分析哪台节点”，分组回答“查看其中哪些查询组” |
| 复用 `QUERY_TEXT` 聚合字段 | 与原 DPM 的趋势模板一致，延续已有查询方式 |
| 将数量交给 `top` | 由拥有数据和聚合规则的服务端选择分组，前端不凭显示名称猜测分类 |
| 每个返回分组独立绘制 | 避免把不同查询的性能变化混成一条曲线，便于比较波动 |
| 使用真实时间点 | 保持数据的实际时间位置，避免按数组序号绘图造成时序误读 |
| 不把选中组相加为节点总速率 | Top 结果可能不完整，分组互斥、分母和覆盖范围尚未确认 |
| 不在前端归一化 SQL | 参数、字面值、实例范围和查询语义可能不同，简单替换可能错误合并 |
| 区分设计意图与接口实测 | 请求参数表达了需求，但不能单凭参数推定服务端已兑现全部契约 |

该设计用于比较查询组的时间变化，不承担“数据库整体总速率”的完整性承诺。若需要节点整体事务速率，应另行确认整体范围的时序请求与指标口径，不能把 Top 分组求和代替整体趋势。

## 6. 请求 API 与配置保存

### 6.1 平均事务速率请求

请求业务目标为已配置的数据源地址。本场景为：

```text
https://101.254.114.236/webservice/NetInside
```

截图配置对应的参数模板为：

```text
type=getTroubleshootData
start=1791820800
end=1791907200
top=5
dataType=ScriptTimeDataSet
dataTypeLabel=Average Transaction Rate (#/min)
visibleColumns=QUERY_END_TIME
selection=<所选节点的真实选择条件>
aggrField=QUERY_TEXT
label=TransactionRate
csv=true
```

起止时间对应北京时间 2026-10-13 00:00 至 2026-10-14 00:00。`selection` 使用所选节点的实际标识或完整条件；不要把界面显示名称任意拼成复杂筛选条件。

`visibleColumns=QUERY_END_TIME` 是既有时序模板的参数，不代表返回结果只有一列。指标值列由所选数据集标签和响应结构决定。

当前趋势请求没有传入新的粒度参数、SQL 归一化参数或 Top 排序指标。后续若需要这些能力，应先验证服务端支持，再设计控件，不能只增加界面字段。

### 6.2 同源代理与编码

前端复用既有平台登录及同源代理，请求业务后端仍为 236。平台认证目标和被监控节点不改变数据库业务请求目标。

业务 URL 的参数名、参数值分别编码，再对完整业务 URL 编码后传给平台代理的 `url` 参数。完整选择条件不重复解码，不随意改变大小写，不导出 Cookie。

### 6.3 保存与回显

当前相关配置保存在 API URL 的 `#nop-dpm-v1=` 配置片段中，时间起止值位于 URL 请求参数中。以下为结构示意：

```json
{
  "version": 1,
  "contractVersion": 2,
  "provider": "dpm",
  "objectType": "Database",
  "view": "timeseries",
  "timeMode": "fixed",
  "metrics": ["TransactionRate"],
  "selection": "<真实节点条件>",
  "limit": 5,
  "singleNode": false
}
```

示意选择条件不能直接作为有效请求使用。重开配置时，应原样回显 `limit`、节点、指标和时间模式，不重新设回默认 5，也不将 `limit` 解释为时间粒度。

## 7. 分组契约：后端必须确认的事项

本专题实施或调整前，应形成如下契约表：

| 问题 | 需要取得的证据 | 当前状态 |
| --- | --- | --- |
| Group 是否确实对应 QUERY_TEXT 分组 | 同区间的真实响应与服务端说明 | 请求意图明确，业务对应关系待专题实测 |
| SQL 按原文还是指纹归组 | 带不同字面值、参数化语句的受控对照或服务端契约 | 未确认 |
| 相同 SQL 跨实例是否合并 | 明确实例范围的对照 | 未确认 |
| top 作用于分组还是其他对象 | top=1、5、10 的同条件响应比较 | 未确认 |
| Top 选择按什么排序 | 服务端排序规则或可重复、可解释的受控数据 | 未确认 |
| 分组是否互斥、覆盖全部范围 | 分类定义、完整性标志、同口径整体校验 | 未确认 |
| 是否有稳定分组标识 | 响应中的键与跨刷新稳定性 | 未确认，当前前端使用 Group 标签 |
| 时间点表示采样时刻还是时间段边界 | 数据集契约及采集说明 | 未确认 |
| 速率统计分母、精度和单位 | 服务端定义与响应表头 | 默认标签为次/分钟，精确算法待确认 |
| 合法无数据如何返回 | 空表、空正文、null 的接口约定 | 本专题需分别验证 |

不能用其他接口的 `top` 截断结果、实例 × 命令计数守恒或某个节点的单次趋势图，证明上述全部规则。

## 8. 数据模型、解析与曲线转换

### 8.1 当前返回结构处理

当前时序解析器读取：

- 时间列：`QUERY_END_TIME` 或已定义的时间列别名，例如 `Time (seconds)`。
- 指标列：字段别名或该曲线的指标标签。
- 分组列：`Group`；没有该列时，当前实现使用空分组标签。

同一指标下，不同 `Group` 建立不同系列。当前系列名称形如“平均事务速率 · 返回分组标签”。

下面是虚拟数据，仅说明结构，不是 236 的实际 SQL 或真实响应：

```csv
Group,Time (seconds),Average Transaction Rate (#/min)
查询组 A,1791820800,10
查询组 A,1791820860,12
查询组 B,1791820800,4
查询组 B,1791820860,6
```

它形成两条曲线，每条包含两个实际时间点。趋势分组数和每组时间点数是两个独立概念。

### 8.2 分组键与显示标签

当前实现以清理展示标记后的 `Group` 标签查找系列，没有在时序模型中使用独立分组 ID。因此，同名分组、显示标记清理及长 SQL 标签需要专项验收。

后续设计要求：

1. 若接口提供已验证的稳定标识，分组键与显示标签分开存储。
2. 不以截断后的图例文字作为键，不自行合并“看起来相似”的 SQL。
3. 若只有 Group 标签，明确其临时标识性质；发现无法区分的名称碰撞时给出可识别状态，不静默求和。
4. SQL 按纯文本处理；展示转义与业务分组判断分离，不通过 HTML 展示转换改变 SQL 比较符号或条件语义。

### 8.3 时间点与缺失处理

当前实现保留每条曲线的实际样本，按真实时间戳绘制；同组同时间的多个样本保存在数组中，没有自动平均或去重。

多系列展示对齐时使用时间戳及出现序号。出现序号只是前端的位置对齐信息，不表示已经确认不同组的第 N 个重复点属于同一次采样。

| 情况 | 设计要求 |
| --- | --- |
| 数值明确为 0 | 保留零值，不能当作空数据 |
| 数值为 null／缺失 | 保留缺失状态，不补零 |
| 分组只有一个有效时间点 | 显示可见数据点，避免看起来像没有数据 |
| 同时间有多个样本 | 保留样本，不擅自求和或平均；复核服务端统计段含义 |
| 不同组采样时间不同 | 各自按实际时间点绘制，不伪造同步采样 |
| 分组标签缺失 | 当前解析行为如上；产品展示建议标为“数据源未提供分组标签”，不能当作整体统计的证明 |

## 9. 界面设计

建议保留现有“趋势分组数”名称，并增加紧邻说明，帮助用户理解它与节点、时间粒度的区别。

| 控件 | 当前／建议行为 | 设计原因 |
| --- | --- | --- |
| 分析对象 | 选择数据库或数据库客户端 | 确定节点条件类型 |
| 查询时间 | 跟随页面或自定义 | 明确分析窗口，不能混用不同窗口的分组和数值 |
| 分析内容 | 趋势分析 | 与分类统计区分 |
| 节点 | 必选真实节点 | 限定查询范围 |
| 数据库指标 | 平均事务速率单独配置图表 | 避免与秒单位的响应时间共用数值轴 |
| 趋势分组数 | 保留默认 5、整数校验；范围调整需接口验收 | 控制请求数量，保持旧配置兼容 |
| 时间粒度 | “使用数据源返回的时间点” | 当前没有可用粒度参数 |
| 已返回分组数 | 建议在诊断信息或加载结果中显示 | 区分请求数量与实际结果数量 |

建议控件说明文案：

> 向数据源请求的查询趋势分组数量。当前请求按 SQL／查询文本维度聚合，每个返回分组单独展示曲线；不控制时间点数量或采样间隔。分组及 Top 选择规则以数据源为准。

建议结果说明采用事实，例如“请求分组数：5；实际返回：3”，不把“少于请求数量”自动当作失败，也不宣称返回的是最活跃的 3 组。

这些文案及结果计数为设计建议，当前源码没有新增本次建议的提示或诊断控件。

## 10. 绘图、提示与异常状态

### 10.1 绘图规则

1. 横轴使用真实时间；Unix 秒在绘图边界转换为毫秒，不在数值逻辑中混用两种时间单位。
2. 每个返回分组独立绘制，显示指标名称和可辨识的分组标签。
3. 纵轴及提示使用实际单位；不能套用旧网络图中的单位转换规则再次转换。
4. 单有效点显示标记；全零系列仍保留。
5. 长标签可以视觉截断，稳定键不截断；完整名称的查看方式需结合用户权限和画布可读性设计。
6. 不把 Top 分组求和作为节点整体趋势，不把平均响应时间与事务速率混为同一单位。

当前代码已使用时间轴、实际样本点、单点标记、转义后的提示和无有效趋势点提示。稳定颜色、名称碰撞处理、完整标签查看及所有状态的端到端表现仍需按下列方案验收。

### 10.2 状态表

| 状态 | 应显示的内容 |
| --- | --- |
| 加载中 | 当前节点、时间与请求状态，防止旧曲线被误认成新范围数据 |
| 有有效数据 | 实际返回的分组曲线和单位 |
| 只有零值 | 真实零值曲线或点，不显示“无数据” |
| 合法空表 | 当前范围未返回查询趋势分组 |
| 空正文、null、HTML 或结构异常 | 明确的数据／接口异常，不能自动转换为合法空表 |
| 字段缺失 | 指明缺少时间或指标列，保留错误状态 |
| 部分请求失败 | 标明本轮数据不完整，避免新旧系列混用 |
| 返回分组数超过请求数量 | 保留事实并记录数量差异，不凭未确认的排序规则自行截断 |
| 参数变化后的迟到响应 | 不覆盖最新查询范围的结果 |

状态表是验收目标，不是对当前所有编辑器、预览和异步场景已通过验收的声明。

## 11. 请求快照、刷新与兼容

每轮查询应固定数据源、对象、节点选择条件、时间范围、指标和分组数。缓存键或请求标识应包含全部这些条件。

- 自定义时间：刷新沿用保存的起止时间。
- 跟随页面时间：本轮开始时取页面时间快照，多个指标请求使用同一快照。
- 切换节点、时间、指标或分组数：使旧请求及旧缓存失效。
- 迟到响应：按请求代次检查，不能覆盖新范围。
- 组件退出：停止后续提交，必要时取消未完成请求。

这些异步保护需核对实际编辑器和预览调用链。仅在 `executeDpm` 中看到多个请求并发执行，不代表所有入口已具备上述保护。

保存兼容要求：不更改既有 `limit` 的含义；旧配置回显原分组数；界面名称调整不改变保存字段；如新增 SQL 分组方式、排序或粒度参数，另行设计版本与迁移规则。

## 13. 接口验证与验收方案

### 13.1 真实接口对照

选择有数据库查询记录的固定节点和时间窗口，采用同一登录代理、相同指标与相同节点条件，依次测试 `top=1`、`top=5`、`top=10`。本次文档没有执行这组新的真实请求。

记录接口类型、时间、top、响应状态、时间列、单位、分组数及各组样本数，比较：

1. top 是否改变分组数量或其他响应内容。
2. 返回组数小于、等于、大于 top 时的真实情况。
3. Group 与 QUERY_TEXT 的业务对应关系及稳定标识。
4. 相同条件的分组集合、排序及样本是否可重复。
5. 换时间范围后返回分组与数值是否一起更新。
6. 数据库客户端的范围是否与其节点条件一致。

SQL 归一化验证使用获得授权的受控样例或服务端说明；不为了确认分组规则而任意创建生产数据。日志只保存匿名分组编号、摘要、数量和结构，不保存真实 SQL 正文、Cookie 或认证信息。

### 13.2 前端验收用例

| 用例 | 期望 |
| --- | --- |
| limit=5 构造请求 | top=5，保留 QUERY_TEXT 聚合与节点条件 |
| 返回 3 组 | 显示真实 3 组，不凑成 5 组 |
| 返回 0 组合法表 | 提示无趋势分组，不保留默认样例图 |
| 每组多个时间点 | 分组数和样本数分别处理 |
| 零值、null、缺列 | 真实零值保留，缺失不补零，缺列明确报错 |
| 同时间多个样本 | 保留样本，不静默平均或去重 |
| 不同组时间错开 | 保留各自真实时间位置 |
| 只有一个有效点 | 有可见点和可辨识提示 |
| 长 SQL、比较符号和展示标记 | 纯文本安全展示，分组含义不被展示转换改变 |
| 同名不同业务组 | 稳定标识区分，或报告无法区分；不静默合并 |
| 快速切换节点或时间 | 迟到响应不能覆盖新范围 |
| 保存、重开、预览 | 分组数、节点、时间模式、指标和单位一致 |
| 混选响应时间与事务速率 | 按当前单位约束阻止不合理混图 |

### 13.3 完成标准

用户能够清楚区分节点、SQL／查询文本分组、指标和时间点；接口实测明确 Group 的含义与 top 的作用；每条曲线可追溯到真实返回分组和样本；请求数量与实际分组数表达准确；没有虚构分组、补零、重复单位转换或旧图冒充新数据；保存与预览结果一致。

## 14. 实施顺序与相关文档

1. **接口契约验证**：完成 Group、top、排序、采样窗口和单位的专题对照，形成证据表。
2. **解释与状态完善**：补充控件说明、实际返回分组数和必要的错误状态；保留旧配置。
3. **分组模型与展示完善**：在接口证据支持下完善稳定键、标签、重复点、颜色和异步保护。
4. **真实画布验收**：覆盖编辑器正常操作、固定时间、页面时间、刷新、保存重开和预览。
