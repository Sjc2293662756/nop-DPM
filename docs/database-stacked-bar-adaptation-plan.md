# 数据库横向、纵向堆叠柱状图适配方案

日期：2026-10-13。状态：已取得原生查询数交叉数据，堆叠绘图待实施。

2026-10-14 已对 236 发起真实请求，取得实例到命令的交叉筛选证据。后续通过 `getTopGroups / QUERY_COMMAND=?` 取得真实命令查询数，两个实例、两个时间窗的分项合计精确等于父计数，重复稳定；不再采用逐个命令 Id 补查总数的方案。详见 [首轮实测](database-stacked-bar-interface-validation-20261014.md) 和 [最新诊断与可用请求](database-user-proc-query-diagnosis-20261014.md)。完整性仍应在每轮执行中校验；速率精度及其他组合尚未确认。

适配对象：横向堆叠柱状图 `hengxiangduidiezhuzhuangtu`、纵向堆叠柱状图 `zongxiangduidiezhuzhuangtu`。

本次仅落本文档，不修改代码、运行服务配置或用户大屏配置。当前两个数据库堆叠组件仍是单系列统计；真正的分项堆叠尚未完成。

## 1. 目标与关键决策

目标是在一个主分类中，展示同一业务量由哪些互不重叠的分项组成。两种图共用查询与数据模型，只改变坐标方向。

本方案确定：

1. **分析内容保持单选**，决定主分类，例如数据库实例。
2. 新增**分项维度单选**，决定每根柱子中的组成部分，例如查询命令。
3. **数据库指标保持单选**，同一张图各色系列使用同一指标、单位和统计口径。
4. 先验证接口能提供真实交叉数据，再开放相应组合；不能以单维表直接推算交叉结果。
5. 当前单系列模式保留，旧配置不自动改成分项堆叠。
6. 本期规划绝对数值堆叠；百分比堆叠、混合单位、多指标并排堆叠不纳入第一版。

举例：分析内容选择“数据库实例”，分项维度选择“查询命令”，数值选择查询数。每根柱子代表一个实例，颜色分别代表 SELECT、INSERT、UPDATE 等命令。

这里的颜色系列来自**同一个指标的不同类别**，不来自多个分析内容或任意多个指标。

## 2. 当前实现与缺口

| 方面 | 当前实现 | 真正堆叠需要补充 |
| --- | --- | --- |
| 分析选择 | 可以选择适配的分类统计分析 | 根据主分类提供经过验证的分项维度 |
| 指标 | 最多一个指标，单系列统计 | 仍选一个指标，但生成多个分项系列 |
| 后端结果 | 多数接口返回一个分组维度的统计表 | 同时包含主分类与分项的交叉数值，或可按父分类分别获取子分项 |
| 绘图 | 数据库单系列模式会去掉 ECharts `stack` 属性 | 经语义和完整性校验后给所有分项使用同一堆叠组 |
| 数据源 | 前端经平台同源代理查询已配置的 DPM 数据源 | 继续使用现有链路，本场景数据库业务目标为 236 |
| 元数据 | 指标与分析模板在前端定义 | 增加前端分项能力定义，不新增 NOP 后端指标目录请求 |

当前实例、应用、命令接口主要返回平均性能和速率，不能假定它们具备查询总数，也不能以“指标目录里存在查询数”为证据认定该分析接口会返回查询数。

运行统计目前是独立的多维度下钻树表，顶层分类可能没有数值。不能把树表中“实例、应用、命令”等不同维度并列行当成组成部分；如使用其下钻数据，必须证明具体分支确实提供所需交叉关系。

参考：[总体适配规划](database-chart-analysis-plan.md)、[运行统计树表实施记录](database-runtime-tree-v1-20261010.md)、[运行统计展示设计](database-runtime-tree-display-design-20261010.md)。

## 3. 组合范围与开放顺序

先建立一套明确的组合能力表，未验证的组合显示为受限项。首个业务目标为“数据库实例 × 查询命令”。

| 主分类 / 分析内容 | 分项维度 | 用途 | 开放条件与顺序 |
| --- | --- | --- | --- |
| 数据库实例 | 查询命令 | 比较各实例的访问组成 | 首个目标；先证明实例筛选条件、分项值和可加性 |
| 节点统计 | 查询命令 | 比较各数据库节点的访问组成 | 可先作为接口技术探针；通过后可作为独立组合开放 |
| 数据库应用 | 查询命令 | 比较各应用的访问组成 | 后续扩展；需证明应用范围筛选有效 |
| 查询命令 | 数据库实例 | 比较某类命令由哪些实例产生 | 只在交叉数据支持此方向时开放；不能用独立实例表与命令表拼接 |
| 客户端访问的数据库 | 查询命令 | 比较该客户端访问各数据库的组成 | 后续扩展；父条件必须同时保留客户端和目标数据库范围 |
| 运行统计 | 特定、已验证的下钻维度 | 使用树表分支中的组成关系 | 保持条件能力；不开放任意树层级混合堆叠 |
| 慢事务、语句明细 | 不预设 | 事件记录与语句响应分析 | 本期不开放；尚无明确的互斥组成定义，语句接口亦未取得有效验收结果 |
| 趋势分析 | 不预设 | 时间序列 | 本期不开放时间堆叠，另行定义时间分桶与统计口径 |

“实例 × 命令”是待验证的产品目标，不是当前接口能力承诺。若接口阶段无法取得有效交叉数据，应停止开放该组合，保留单系列或引导使用普通柱状图，不伪造组成关系。

## 4. 统计口径与指标规则

### 4.1 可以考虑的指标

| 指标类型 | 候选 | 必须确认的条件 |
| --- | --- | --- |
| 查询总数 | `QUERY_COUNT` | 父分类和子分项接口均实际返回该指标，分项覆盖同一范围 |
| 返回总量 | `BYTES_RETURNED` | 同一单位、相同采集口径、分项不重复计量 |
| 返回包数 | `PACKETS_RETURNED` | 同一对象和范围，包计数分项互斥 |
| 影响行数 | `ROWS_AFFECTED` | 后端明确其按分项可加，不能以查询次数代替 |
| 查询、返回量、包数、影响行数速率 | 对应 `*_RATE` | 时间窗、分母、归一化方式一致，且后端确认分项速率可相加 |

优先验证查询总数。如果分组接口只有速率，则在分母和归一化方式验证前保持置灰。**不能用速率乘时间窗推算总数**，也不能把“次/分钟”相同当作分母相同的充分证据。

### 4.2 禁止直接堆叠的指标

- 平均最终响应时间与平均首包响应时间：既是平均值，也有重叠含义。
- 查询数与影响行数：不同业务量，即使列头都显示“个”也不能相加。
- 返回总量与平均返回量：总量和平均值的口径不同。
- 同一指标的整体值与它的子分项：会重复计数。
- SQL 文本、时间、标识：用作标签或条件，不作为柱子的长度或高度。

单系列比较模式仍可以展示平均指标；切到分项堆叠模式时必须重新检查指标，不沿用不适合相加的平均值。

## 5. 界面设计

在现有“编辑数据”弹窗中复用数据源、分析对象、时间、节点和排序配置，增加以下设置。

| 设置 | 建议交互 | 说明 |
| --- | --- | --- |
| 展示方式 | 单系列统计 / 分项堆叠 | 旧配置默认保持单系列；用户明确选择后才启用堆叠 |
| 分析内容 | 单选 | 作为主分类，例如数据库实例 |
| 分项维度 | 单选，受主分类约束 | 例如查询命令；显示未开放的原因 |
| 数据库指标 | 单选 | 仅提供经过该组合验证的可加指标 |
| 主分类数量 | 数字输入，默认 5，第一版上限建议 20 | 控制展示范围和按父分类查询时的请求规模 |
| 分项范围 | 第一版优先完整命令集合 | 未确认完整性时不以截断结果计算总高或总长 |
| 分类排序 | 按完整柱子的合计值，或已验证的父分类总值 | 不完整分类不能参与正常数值排名 |
| 图例 | 每个分项对应一个颜色 | 相同分项在不同父分类、两种方向和刷新前后颜色一致 |

顺序示例：

```text
数据源 → 分析对象 → 查询时间 → 展示方式：分项堆叠
      → 分析内容：数据库实例 → 数据库节点
      → 分项维度：查询命令 → 指标：查询数
      → 主分类数量与排序 → 确定
```

切换主分类时清除不适用的分项维度和指标；切换指标时重新验证单位和可加性；切换数据源、节点或时间时使旧请求和缓存失效。

禁用提示应具体，例如：

- “该数据源尚未验证实例到命令的分项筛选条件。”
- “此分析当前只返回平均值，不能作为堆叠组成。”
- “分项速率的统计分母尚未确认，暂不开放。”
- “当前分项结果不完整，无法显示可靠的合计柱。”

## 6. 数据获取方案

### 6.1 先验证接口契约

实施第一步是向 236 核实以下事项：

1. 主分类是否有稳定的业务标识，显示名称是否可能重复。
2. 后端返回的父行 `id`/`Id` 是否可用于分项接口的 `selection`。
3. 分项请求是否确实限定在所选父分类内，而不是仍然返回整个节点的数据。
4. 目标数值字段是否存在，单位、统计方式和速率分母是否一致。
5. 分项是否互斥、是否覆盖完整范围，`top` 参数是否会截断结果。
6. 是否有原生交叉查询、完整性标记或可用于校验的父分类总值。

`id` 只作为候选条件来源；必须对照原 DPM 的实际调用或接口验证确认其用途。不能因为字段名为 `Id` 就认定它适用于任何接口。之前语句接口的无效结果也说明该对应关系需要单独验证。

参数编码规则同样需要确认：对原始筛选条件正确编码；若后端给出已编码片段，应先明确其格式，不固定地重复编码或任意解码。

### 6.2 优先使用已验证的原生交叉结果

如果已有 DPM 接口能一次返回主分类、分项和目标指标，优先使用，减少多请求造成的范围差异和部分失败。

2026-10-14 实测已确认：`getTopGroups` 在父实例范围内按 `QUERY_COMMAND=?` 分组，可一次返回该实例各命令的真实查询数。使用这条已验证的原生分组链路，再按父实例分别组成矩阵；不是一次取得所有实例和命令的二维表。请求及证据见 [诊断记录](database-user-proc-query-diagnosis-20261014.md)。

### 6.3 条件方案：按父分类分别查询分项

在原生交叉查询缺失、但父筛选条件已验证的情况下：

1. 固定本轮数据源、对象、节点、开始及结束时间，形成查询快照。
2. 获取主分类列表，例如指定节点的数据库实例。
3. 选取明确的 Top N 父分类，保存各自的真实标识和已验证筛选条件。
4. 对每个父分类请求查询命令统计，保持同一时间范围、指标和统计口径。
5. 检查字段、分项完整性、父子范围与可加性，再转换为交叉矩阵。
6. 一次性提交本轮图表数据，避免不同轮次的父子结果混用。

候选请求模板沿用现有 DPM 约定：

| 目的 | 现有候选接口与参数 | 待验证部分 |
| --- | --- | --- |
| 节点父分类 | `getTopGroups`，按数据库或客户端节点查询，`json=true` | 父总值和分项是否同口径 |
| 实例父分类 | `getTroubleshootData`，`ScriptTabularDataSet`，`DB Instance` / `InstancesData` | 行标识如何用于下一层筛选，以及实际返回的可加指标 |
| 应用父分类 | 同类接口，`Application` / `ApplicationsData` | 应用范围筛选条件 |
| 命令分项 | 同类接口，`Query Command` / `CommandsData`，`json=true` | 父分类条件是否有效、命令集合是否完整、目标值是否可加 |
| 命令查询数分项（已验证） | `getTopGroups`，父实例范围内 `QUERY_COMMAND=?`，`visibleColumns=QUERY_COUNT,QUERY_COUNT_RATE`，`json=true` | 两实例、两时间窗计数合计已验证；每轮仍检查截断、缺失和父子合计 |
| 客户端关联数据库 | `getPerfData`，`DB Server` | 是否能保留客户端和目标数据库的组合范围 |
| 运行树表分支 | `getRawTable` 与后端给出的已验证分支条件 | 该分支是否对应真实交叉关系，而非并列统计维度 |

实例、应用、命令模板当前要求固定的 `visibleColumns=FINAL_RESP_TIME,DB_INSTANCE,QUERY_TEXT`，返回的显示字段另行映射。未经接口验证不能为了取得总数就任意替换这些请求字段。

不从分类名称、SQL 文本或显示标签自行拼接筛选条件；不向后端新增未经支持的参数。

### 6.4 请求规模与异步保护

第一版建议主分类默认 5、最多 20，并限制最多 3 个分项请求同时执行。已有请求超时约定可沿用，失败分支提供明确重试。

缓存键应包含数据源、对象、节点、父分类条件、时间范围、分项维度和指标。只在相同查询快照内复用数值；不把上一时间段的子结果用于新时间段。

切换条件、再次刷新或组件退出后，迟到响应不能覆盖新图。开发与真实验收辅助文件放在独立目录，避免测试代码引发编辑器刷新。

## 7. 数据模型与转换

### 7.1 统一中间模型

横向与纵向使用同一模型：

- 主分类数组：稳定键、显示名称、对应查询条件。
- 分项数组：稳定分项键、显示名称和颜色。
- 数值单元格：父分类键、分项键、指标值、值状态。
- 查询快照：数据源、对象、节点、时间、指标和单位。
- 完整性状态：每个父分类是否可可靠展示合计。

父分类用真实业务标识区分，同名实例不合并。分项需有可跨父分类识别的类别键；带父范围的整条筛选条件不能直接作为共享分项键。

例如命令类别可在验证后采用其实际命令代码或未经翻译的原始类别值；不能仅凭中文展示名称归并不同分项。重复单元格也不能直接求和，需先确认它们是否是互不重叠的记录，或者属于重复响应。

### 7.2 示意数据

以下为虚拟数据，只用于说明形态，不是实际 236 响应：

| 主分类 | SELECT | INSERT | UPDATE | 合计 |
| --- | --- | --- | --- | --- |
| 实例 A | 80 | 20 | 10 | 110 |
| 实例 B | 50 | 30 | 20 | 100 |

转换后的绘图模型可以表达为：

```json
{
  "categories": [
    { "key": "instance-a", "label": "实例 A" },
    { "key": "instance-b", "label": "实例 B" }
  ],
  "metric": "QUERY_COUNT",
  "unit": "个",
  "series": [
    { "key": "SELECT", "name": "SELECT", "values": [80, 50] },
    { "key": "INSERT", "name": "INSERT", "values": [20, 30] },
    { "key": "UPDATE", "name": "UPDATE", "values": [10, 20] }
  ],
  "categoryStatus": ["complete", "complete"]
}
```

单位由实际响应决定，不固定为示例中的“个”。主分类排序后，所有系列同步重排，不能分别排序各分项。

### 7.3 缺失与零值

明确区分：

| 情况 | 处理 |
| --- | --- |
| 后端明确返回 0 | 保留真实零值 |
| 完整结果中确认某分项不存在，且契约明确其值为 0 | 可记为“确认不存在”的零值，保留判断依据 |
| 字段值缺失或为 null | 保留缺失状态，不补 0 |
| 分项因 Top 截断未返回 | 标记结果不完整，不把未返回项当作零 |
| 父分类请求失败 | 标记失败分支，不能画成零高柱 |
| 合法空结果 | 按接口契约说明无记录；未确认其含义时不自动将整个矩阵补零 |

第一版建议默认采用“阻止不完整父分类合计”的策略：保留该分类及状态提示，但不绘制看似完整的总柱；可在明细中查看已有值并重试。其他完整分类是否展示，应明确标注本轮存在不完整分类。

### 7.4 合计校验与“其他”

如果存在同口径的父分类总值，校验分项合计与父总值是否相符。计数类优先精确校验；浮点总量或速率的容差基于响应精度和单位定义，不通过取整强行对齐。

第一版默认不计算“其他”。只有父总值可信、范围一致、分项互斥、截断含义明确且无失败分支时，才可以另行开放“父总值 − 已返回分项和”。差额为负时必须报错，不能裁成 0。

返回行数少于 `top` 不能单独证明结果完整；运行统计已有返回规则也说明数量参数需要逐接口验证。

## 8. 绘图适配

| 项目 | 横向堆叠 | 纵向堆叠 |
| --- | --- | --- |
| 分类轴 | 纵轴 | 横轴 |
| 数值轴 | 横轴 | 纵轴 |
| 每个分项 | 一条横向系列 | 一条纵向系列 |
| 堆叠方式 | 同一父分类内沿长度相加 | 同一父分类内沿高度相加 |
| 长名称 | 适合直接显示，仍可截断并提示全名 | 适当旋转或截断，并提示全名 |

绘图层完成：

- 分项系列使用同一个堆叠组；图例名称使用分项类别，不使用不同指标名称。
- 相同分项的颜色稳定，不因某个父分类缺项或返回顺序变化而改变。
- 提示显示父分类、各分项值、同一单位、合计和完整性状态。
- 默认按完整合计排序；不完整项单独标注并放在后面，不参与数值排名。
- 全零结果提示总量为 0，缺失或失败结果不显示虚构合计。
- 图例隐藏部分系列时，提示区别“全部分项合计”和“当前可见分项合计”，避免改变总量含义。
- 两种方向的数据、分项顺序、颜色、单位与总值一致。
- 查询失败或加载新范围时清除不相干旧图，不继续展示“近一周、5月”等默认样例。

建议抽取共用的堆叠数据转换与刷新模块，编辑器和预览都使用；方向仅影响坐标和样式，不复制两套查询与错误处理流程。

## 9. 保存兼容与代码改动范围

保留现有 API 配置片段及外层配置版本，不直接让旧版本误执行新增模式。为堆叠增加独立版本信息、模式、分项维度和完整性策略；字段最终名称在实施时确定。

示意配置如下，同样不是已实现接口参数：

```json
{
  "view": "instances",
  "metrics": ["QUERY_COUNT"],
  "stackMode": "partition",
  "stack": {
    "version": 1,
    "partitionView": "commands",
    "categoryLimit": 5,
    "partitionLimit": 20,
    "missingPolicy": "block-category",
    "includeOther": false
  }
}
```

该示例只有在实例与命令组合实际支持查询总数时才有效；当前分组指标白名单与查询生成器不能直接接受它，需要明确的组合能力与执行器适配。

旧的单系列配置原样保留。用户切换为分项堆叠时再校验并生成新配置；不截取旧多指标配置、不把多个指标解释成分项。

预计涉及：

| 区域 | 预计职责 |
| --- | --- |
| `capabilities.js` | 区分单系列与分项模式，定义已验证组合和可加指标 |
| `catalog.js` | 前端分项元数据及已确认的指标属性 |
| `DatabaseFields.vue`、`ApiModal.vue` | 新模式、分项选择、提示、校验及配置回显 |
| `query.js` 或新增堆叠查询模块 | 验证过的交叉请求及父子查询计划，不破坏原单维模板 |
| `execute.js` 或新增组合执行模块 | 请求快照、并发、缓存、失败与合计校验 |
| 新增堆叠数据模块 | 稳定键、矩阵对齐、完整性状态及排序 |
| `charts.js`、`moduledefault.js` | 公共状态、堆叠系列、坐标方向与提示 |
| 编辑器与预览 | 共用执行及绘图入口，静态/数据库切换与错误恢复 |

运行树表继续独立维护，只在具体分支能力经过验证时复用数据获取，不把树表整体改成堆叠图数据。

## 10. 实施步骤与验收

### 阶段一：接口可行性验证

使用有明确数据的时间和节点，对比原 DPM 调用与 NOP 请求。逐项确认父条件、子分项、数值、单位、完整性及合计关系，形成接口证据表。

可以先用“节点 × 命令”确认基础查询，再验证“实例 × 命令”。仅前一个组合成功时，不宣称实例组合已支持。若没有满足条件的指标或筛选方式，该阶段结论应是暂不开放，不以客户端估算补齐能力。

### 阶段二：公共执行与矩阵转换

先建立复现样例与测试，再实现冻结时间快照、组合请求、稳定键、缺失状态和合计校验。验证同名分类、不同返回顺序、零值、缺失、重复记录、Top 截断、请求失败及迟到响应。

### 阶段三：界面与两种方向

增加模式和分项选择，保留单指标约束；两种方向与预览接入同一个矩阵模型。完成颜色、单位、合计、全零、部分失败及图例筛选提示。

### 阶段四：真实验收与保存往返

对 236 发起合法、有限的查询，同源复用已有登录会话。核对每个父分类的全部分项和柱子合计，验证保存、重开、预览、固定时间、页面时间刷新及恢复旧单系列配置。

验收标准：

1. 主分析与分项维度各自单选，指标仍单选，提示能解释受限原因。
2. 返回数据能够证明父分类与分项的交叉关系，条件和时间范围准确。
3. 分项使用同一业务量、单位、统计口径，互不重复；平均值不直接相加。
4. 矩阵中的每个值与响应对应，排序不打乱分类关系，同名分类不合并。
5. 缺失、未返回、失败与零值分别处理，不完整数据不伪装为完整合计。
6. 真实分项合计与可信父总值符合已声明精度，不能任意推算“其他”。
7. 横向、纵向、编辑器与预览展示同一数据、颜色、单位和状态。
8. 旧配置不自动改变含义，新增配置完整回显。
9. 验收记录分别标明已支持、无数据、未验证和失败，不将 HTTP 200 当作全部通过。

开发前备份文件，并确认当前大屏是否保存，避免热更新丢失草稿。日志记录参数结构、状态及校验结论，不记录 Cookie、密码或 SQL 正文；测试辅助代码不进入生产静态资源目录。

## 11. 暂不实施的能力

第一版不包含百分比堆叠、任意多指标堆叠、任意运行树分支组合、时间堆叠、语句级组成、跨数据源拼接，以及未经确认的速率总数换算。

阶段一现已取得可重复的实例 × 命令查询数证据，下一步可实施公共请求执行器与矩阵转换，再接入横向、纵向绘图。每轮保留精确计数合计和完整性校验，不自动开放其他未经验证的指标或组合。
