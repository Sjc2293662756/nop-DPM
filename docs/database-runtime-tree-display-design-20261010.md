# 数据库运行统计树表展示设计与验收纠正

日期：2026-10-10。状态：第一版树表已实施，实际范围与验收见 [第一版记录](database-runtime-tree-v1-20261010.md)。下文保留设计依据与此前缺陷分析，待验收建议不代表所有路径都已通过。

用户提供的现有“数据库运行监测”界面显示，运行统计是多种分析维度组织成的可展开树表。SQL、查询命令、返回码、实例、用户、客户端地址、应用等顶层行是维度入口，其子行才展示对应统计值。不同维度会重复描述同一批数据库访问，不能把这些维度入口当成互斥分类求和、求占比或混合排名。

## 当前空白的原因

DPM 参考代码 `js/script.js` 的 `auto_table_lClick_json2` 为返回行保留 `id` 并绘制展开按钮；其 `getData(urlId)` 在点击展开时把该真实行标识作为 `selection` 再次调用 `getRawTable`。数据按层级查询，不应假设初始响应已经包含全部子行。

NOP 当前 `normalizeTable` 只转换初始 `rows`；`reBiaoge` 将这些行变成平面表格，编辑器和预览没有对应的展开查询逻辑。用户截图里有分类名称而没有统计值，符合只显示顶层维度的情况。取消指标选择本身不能解决子级尚未取数的问题。

此前实测的运行统计 11 行及字段映射只覆盖顶层响应；其 PASS 不能代表子级统计值、展开交互、每组 Top N 或完整运行统计功能已通过验收。原始日志保留，不改写原测试结果；功能状态应记为树表适配未完成。

## 展示方案

- 仅作为表格分析展示，增加树形展开、收起；顶层维度名称适当中文化，子行保留真实对象名称。名称列固定在左侧。
- 顶层分类没有值时留空或显示“—”，不能补 0，也不按数值对顶层维度排序。
- 默认展示六列：分组名称、平均最终响应时间、平均首包响应时间、事务速率、返回数据速率、影响行数速率。列名和单位以该接口实际响应为准。
- 不要求用户先选择一个指标；自动使用默认列。可选的“显示列”设置用于隐藏或追加接口真实支持的列，不承担决定树表结构的职责。
- 展开使用后端返回的真实行标识/选择条件，不从显示名称或 SQL 文本拼接请求。缺少有效标识时不能假装可下钻。
- 每个节点分别显示加载、合法空结果、失败与重试状态；切换数据库、客户端或时间区间后取消过期结果并清理展开缓存。
- 配置保留节点、时间、每组 Top N、排序指标和可选搜索条件。“每组 Top N”作用于子级条目，不应把顶层维度行数当作 Top 是否生效的证据；具体参数效果仍需真实展开查询验收。
- 同一维度内按选定指标排序，保留父子关系。同名条目不擅自合并，平均值不合计。SQL 展示可省略长文本并提供查看入口；验收日志不记录 SQL 正文或敏感选择条件。
- 编辑器与预览采用同一树表适配。第一版已在普通柱状图、构成图、堆叠图、趋势图和单值图中置灰此综合分析，具体维度比较使用已有实例、应用、命令等专门分析。

## 后续验收

需要验证两类对象的顶层及至少两级展开、服务端选择条件原样使用、叶子数值/单位、排序和每组数量、同名记录、空值与零值、失败重试、时间或节点切换时的迟到响应，以及配置重开和预览。补齐这些检查前，不能将运行统计标为完整可用。

设计阶段仅确认结构并修正文档状态；后续第一版实施与实测见前述实施记录。
