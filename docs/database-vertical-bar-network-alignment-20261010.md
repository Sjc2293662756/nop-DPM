# 数据库纵向柱状图指标数量与网络对齐

日期：2026-10-10。

用户在了解网络普通柱状图的指标数量限制后，决定数据库部分保持一致。本轮针对当前适配的普通纵向柱状图，恢复每次最多选择 **一个数值指标**。此前多指标实现和实测保留为历史记录，不代表当前开放能力。

## 当前行为

- 数据库和网络普通纵向柱状图均最多选择一个指标，下拉框使用同一数量约定：`multiple-limit=1`。
- 既有单指标配置、分析列表和指标目录继续使用；节点、时间、排序和固定接口模板约定保持不变。
- 已保存的多指标配置重开时保留原选择并显示限制原因，提交被阻止；用户明确移除多余指标后才可继续。不自动截取第一个指标或更改统计含义。
- 编辑器和预览执行多指标旧配置时在请求前拒绝，清除旧图并显示错误，避免误以为所有指标仍在展示。
- 保留原来的实际单位、零值与缺失值、合法空表、错误重试、固定历史时间、页面时间刷新、迟到响应保护和静态切换修复。
- 多指标系列颜色与分轴代码恢复为之前的单指标实现。其他图表能力按各自既有规则处理，本轮没有扩大或取消其业务限制。

## 验证与证据

新增限制测试验证网络与数据库普通柱状图数量一致、旧多指标请求在发送前被阻止、编辑器与预览清除旧图、弹窗保留旧选择并要求用户明确移除后再提交。原数据库与平台会话回归也覆盖单指标的数值、单位、时间和配置重开。

本轮相关回归共 14 个文件、151 项全部通过；修改模块和测试通过 ESLint，字段组件模板编译无错误，隔离生产构建成功，8080 开发服务编译成功且页面返回 HTTP 200。

结果见 [回归结果](../../backups/vertical-bar-network-alignment-20261010/unit-results.json)、[隔离生产构建](../../backups/vertical-bar-network-alignment-20261010/production-build-result.json)。本轮验证的是恢复后的限制及既有单指标行为，没有把历史 33 组多指标实测当作当前能力验收，也没有重复发送数据库业务查询。

恢复前的源码、测试和文档备份位于 `backups/vertical-bar-network-alignment-20261010/before`。历史多指标测试已归档至该目录上一级，不再作为当前允许能力执行。生产构建输出隔离在该 backups 目录，没有覆盖既有生产 dist。本轮没有代用户保存后端大屏或部署远程生产环境。
